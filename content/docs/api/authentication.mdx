---
title: Authentication
description: Exchange your client ID and secret for an access token with POST /oauth/token.
---

Every call to the RipeText API carries an access token. You get one by exchanging your client ID and client secret, using the OAuth 2.0 client credentials grant.

```
POST https://api.ripetext.com/oauth/token
```

The SDK does this for you, including refreshing an expired token, so you only need this page if you're calling the API directly.

## Request

No access token or signature, since this is where the token comes from. Send JSON, or `application/x-www-form-urlencoded` if that suits your HTTP client better.

| Field           | Type   | Required | Description                                |
| --------------- | ------ | -------- | ------------------------------------------ |
| `grant_type`    | string | yes      | Always `client_credentials`                |
| `client_id`     | string | yes      | From **Settings → Integrations → Manage**  |
| `client_secret` | string | yes      | Shown once when the credential was created |

## Response

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "support:ingest support:backfill"
}
```

Send it as `Authorization: Bearer <access_token>` on every other request. The token is valid for **one hour**. Reuse it until it expires rather than fetching one per request: the endpoint allows 20 requests per minute per IP address.

## Scopes

| Scope              | Grants                                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `support:ingest`   | [Sending events](/docs/api/support/endpoints/send-event) and [uploading batches](/docs/api/support/endpoints/upload-batch)          |
| `support:backfill` | [Starting an import](/docs/api/support/endpoints/start-import) and [checking its status](/docs/api/support/endpoints/import-status) |

Credentials are issued with both, and the token always carries every scope its credential has. Calling an endpoint your token doesn't cover returns `403 insufficient_scope`.

## Errors

| Status | Code              | Meaning                                                         |
| ------ | ----------------- | --------------------------------------------------------------- |
| `400`  | `invalid_request` | A field is missing or malformed; `details` lists which          |
| `400`  | `invalid_scope`   | The credential has no scopes. Generate a new one.               |
| `401`  | `invalid_client`  | The client ID or secret is wrong, or the credential was revoked |
| `429`  | `rate_limited`    | More than 20 token requests in a minute from this IP address    |

Error responses are JSON: `{ "error": "invalid_client", "message": "..." }`.

Token requests aren't recorded under **Recent delivery attempts**, because a request that fails here hasn't identified an integration yet.
